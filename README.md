# Помощник магазина X1

Прототип для тестового задания: Telegram-бот и веб-чат отвечают по шести пунктам регламента. Qwen сама пишет текст ответа. Приложение проверяет его перед отправкой клиенту

Бот: https://t.me/ajajjajajajja_bot — нажмите Start и напишите вопрос

Текущий экземпляр работает на компьютере автора, пока включены компьютер, интернет, модель и процесс бота. Для постоянной доступности нужен отдельный сервер

## Как устроены ответы

1. `knowledge_base.json` хранит исходные шесть правил
2. Модель получает системный промпт с регламентом, вопрос отдельным сообщением и контекст приложения: например, что базы статусов заказов нет и обычный срок возврата истёк
3. Qwen формулирует ответ и возвращает JSON: `answer`, `source_ids`, `needs_human`
4. `guards.py` проверяет структуру, числовые значения и критические ситуации: конкретный заказ, просроченный возврат, брак, скидки, отсутствующие сведения и выдуманные действия
5. Если проверки пройдены, клиент получает **исходный текст модели без переписывания**. Если проверка не пройдена, показывается защитное сообщение. При недоступности модели бот сообщает об ошибке

Обычные ответы не собираются из готовых фраз. Статическими остаются команды `/start`, `/help`, `/rules` и сообщения об ошибках. Приложение не проверяет реальные заказы, не оформляет возвраты и не переводит обращения оператору

## Запуск на Windows

Python 3.10+, без дополнительных Python-пакетов:

```text
python setup_local_llm.py
python start_local_llm.py
```

Подготовка скачивает Qwen3.5-2B Q4_K_M из репозитория Unsloth (около 1,28 ГБ) и переносимый llama.cpp с Vulkan. Проверяются SHA-256 файлов. Веса, исполняемые файлы и логи остаются в игнорируемой папке `.runtime`

Открыть http://127.0.0.1:8087. Сервер модели слушает только http://127.0.0.1:8089. По умолчанию выбран `Vulkan0`; на компьютере автора это NVIDIA GTX 1650 с 4 ГБ памяти. Можно указать `--device Vulkan1` для другого устройства или `--cpu` для работы без GPU. Первый запрос может потребовать дополнительного времени

Для Telegram:

```text
python configure_telegram.py
python telegram_bot.py
```

Токен вводится скрыто и хранится через Windows DPAPI в `.runtime`. Альтернатива для сервера — переменная `TELEGRAM_BOT_TOKEN`. Проверка подключения без чтения сообщений: `python telegram_bot.py --check`

Бот принимает только текст личных диалогов. Файлы, группы и сообщения других ботов игнорируются. Long polling не требует открытых входящих портов; существующий webhook автоматически не удаляется. Сохраняется только номер обработанного обновления, без истории и идентификаторов чатов

`python server.py` запускает только веб-приложение. Для ответов нужен настроенный сервер модели; автономного FAQ без LLM нет. Переменные из `.env.example` нужно задавать через окружение — файл автоматически не загружается

## Проверка

```text
python -m unittest discover -s tests -v
```

Автотесты проверяют правила, сохранение исходного текста модели, отклонение опасных ответов, ошибки генерации, HTTP API, адаптеры LLM и Telegram. В них используется тестовая модель; CI не скачивает веса

При работающей настоящей модели, во втором PowerShell:

```powershell
$env:LLM_PROVIDER = 'local'
python run_crash_test.py --require-llm
```

Этот прогон требует, чтобы все три ответа были сформулированы моделью, прошли проверки кода и совпадали с исходным `generated_answer`. Защитное сообщение не засчитывается за успешный ответ. При сбое старые отчёты не перезаписываются

Результаты:

- `CRASH_TEST.md` — фактические ответы на три вопроса задания
- `crash_results.json` — исходные ответы, происхождение текста, идентификаторы вызовов, результаты проверки и расход токенов
- `SYSTEM_PROMPT_FILLED.txt` — основной промпт с регламентом
- `LOCAL_MODEL_INFO.json` — версии, источники и проверенные хеши скачанных файлов

К системному промпту на каждом запросе добавляется JSON контекста из `request_context()` в `assistant.py`. Он содержит факты приложения и разобранный срок возврата, без готового ответа клиенту

## Границы защиты

Отдельные проверки закрывают сценарии задания: неизвестный статус заказа 1842, обычный возврат на 16-й день и просьбу отменить запрет скидок. При браке допускается только экспертиза без обещания немедленного возврата денег

Проверки кода эвристические и не доказывают достоверность любой возможной фразы модели. Для рабочего магазина нужны дополнительные проверки на реальных вопросах, наблюдение за отказами и подключение проверенных источников данных. Проверяется конкретный регламент и сценарии задания, а не универсальная защита от любых галлюцинаций

Вопросы не сохраняются приложением. Веб-интерфейс вставляет ответы через `textContent`; секреты не передаются в браузер. Переписка в Telegram остаётся в самом Telegram. Регламент взят из задания и не моделирует все права потребителя

## Другой провайдер

Поддерживается OpenAI Responses API со Structured Outputs: `LLM_PROVIDER=openai`, `OPENAI_API_KEY` и `OPENAI_MODEL`. В этом режиме вопрос и регламент отправляются провайдеру; ключ хранится только на сервере, `store` отключён. Локальный вариант платного API не требует
