# Помощник магазина X1

Небольшой прототип для тестового: чат, шесть пунктов регламента, системный промпт и воспроизводимый краш-тест. Python 3.10+, без внешних зависимостей.

## Telegram-бот

Проверить: https://t.me/ajajjajajajja_bot

Нажать Start и выбрать один из трёх вопросов или написать свой. Команды: `/start`, `/help`, `/rules`. Telegram и веб-чат используют одну базу, системный промпт и обработчик `answer_question`. Обычные вопросы проходят через настоящую Qwen. Если модель недоступна, бот сообщает об этом и не выдаёт автономный ответ за ответ нейросети.

Текущий экземпляр запущен на компьютере автора: он отвечает, пока компьютер включён, подключён к интернету и работают модель и процесс бота. Для постоянной доступности нужен отдельный сервер.

### Запуск своего экземпляра

1. Создать отдельного бота в @BotFather
2. На Windows выполнить `python configure_telegram.py` и вставить токен в скрытый ввод. Он сохраняется через Windows DPAPI в игнорируемой папке `.runtime`. На сервере можно передать `TELEGRAM_BOT_TOKEN` через окружение
3. Запустить модель командой `python start_local_llm.py`
4. Во втором терминале выполнить `python telegram_bot.py`. Бот по умолчанию выбирает локальную модель

Для проверки авторизации и модели без получения сообщений: `python telegram_bot.py --check`.

Бот принимает текст только из личных диалогов. Группы, сообщения других ботов и редактирования игнорируются; файлы не скачиваются. Long polling не требует открывать входящие порты. Существующий webhook не удаляется автоматически. В приложении сохраняется только номер последнего обработанного обновления, без текста переписки и идентификаторов чатов.

## Запуск с настоящей нейросетью

Для Windows x64, Python 3.10+:

```text
python setup_local_llm.py
python start_local_llm.py
```

Первый запуск скачивает около 1,1 ГБ: модель Qwen2.5-1.5B-Instruct Q4_K_M из официального репозитория Qwen и небольшой переносимый llama.cpp. Скрипт проверяет SHA-256. Установка в систему и платный API-ключ не нужны. Скачанные файлы находятся в игнорируемой папке `.runtime` и не входят в репозиторий.

После старта открыть http://127.0.0.1:8087. Модель работает на CPU с четырьмя потоками, сервер модели доступен только на 127.0.0.1:8089. При первом вопросе возможна задержка. В интерфейсе после ответа показано, использовалась ли настоящая модель или резервные правила.

## Автономный режим без модели

```text
python server.py
```

Без настроек LLM эта команда запускает автономный FAQ. Можно задать свой вопрос или нажать на любой из трёх вопросов задания. База и полный промпт раскрываются под чатом.

```text
python -m unittest discover -s tests -v
python run_crash_test.py --output output/rules
```

## Проверить настоящую модель

При работающем локальном сервере модели, во втором PowerShell:

```powershell
$env:LLM_PROVIDER = 'local'
python run_crash_test.py --require-llm
```

Команда завершится ошибкой, если модель недоступна, вернула неполный ответ или хотя бы один вопрос обработан резервными правилами. После успешного прогона записывает фактические ответы в `crash_results.json` и `CRASH_TEST.md`, а промпт с регламентом - в `SYSTEM_PROMPT_FILLED.txt`. В JSON есть название модели, реальные идентификаторы ответов, темы, число токенов и длительность каждого вызова. `LOCAL_MODEL_INFO.json` содержит сведения о проверенных скачанных файлах.

Проверено 30 автотестами: правила возврата, брак, неизвестные данные, попытки подмены правил, ошибочные ответы модели, HTTP API, адаптеры LLM и обработчик Telegram. Облачный CI запускает эти тесты без скачивания модели; его автономный прогон сохраняется отдельно в output/ci-rules и не заменяет результаты реального LLM-прогона.

## Как устроено

1. `knowledge_base.json` хранит только шесть правил из задания
2. Вопрос разбирается на темы: товар, доставка, возврат, брак, скидка или неизвестное
3. Код отдельно проверяет индивидуальные заказы, срок возврата, брак и запрет скидок
4. Финальный текст собирается из разрешённых правил. Модель не может передать в ответ произвольную цену, статус или обещание
5. У каждого ответа есть ссылки на использованные пункты базы. Если факта нет, бот сообщает об этом и предлагает уточнить у сотрудника. Реального перевода обращения оператору нет

### Как используется LLM

**Без ключа — автономный FAQ (`rules`).** Разбор формулировок выполняется простыми правилами. Он сразу работает и подходит для проверки задания, но не является LLM и не понимает любые перефразирования. Сложную неизвестную формулировку безопаснее не распознать, чем выдумать ответ.

**LLM + проверка регламента (`llm+policy`).** Настоящая модель получает системный промпт из файла, регламент и вопрос клиента отдельным сообщением. Ответ ограничен JSON-схемой со списком тем. Python валидирует результат и формирует текст из базы. Модель отвечает за понимание вопроса; цены, сроки и статусы не передаются ей для свободной генерации. Критические случаи имеют независимые проверки в коде. При ошибке или отказе модели включается явно обозначенный `rules-fallback`.

### Альтернатива: OpenAI API

Переменные задаются перед запуском. `.env` автоматически не загружается. Пример для PowerShell:

```powershell
$env:OPENAI_API_KEY = '<ваш API-ключ>'
$env:OPENAI_MODEL = '<доступная вам модель с Responses API и Structured Outputs>'
$env:LLM_PROVIDER = 'openai'
python server.py
```

Ключ остаётся на сервере, не попадает в браузер и репозиторий. В LLM-режиме вопрос и регламент передаются OpenAI; хранение ответа API отключено параметром `store: false`. Реальные персональные данные для теста не нужны.

## Защита и границы

- По заказу 1842 отсутствует база статусов. Общие условия доставки явно отделяются от статуса конкретного заказа
- Вскрытая упаковка не запрещает возврат до 14 дней; на 16-й день обычный возврат не обещается
- Брак ведёт на экспертизу, без обещания немедленной выплаты и без выдуманного срока экспертизы
- Сообщение клиента не изменяет базу или запрет скидок
- Незнакомые поля и темы из ответа LLM отклоняются; цена, сроки и скидки не генерируются свободным текстом
- Приложение не сохраняет вопросы, браузер вставляет ответы через `textContent`, файлы выдаются по фиксированному списку. Переписка с ботом остаётся в самом Telegram
- Заявлена проверка конкретных сценариев, а не универсальная защита от любых атак. Модель всё ещё может неверно распознать тему; поэтому важны дополнительные evals на реальных формулировках
- Регламент взят из тестового. Проект не трактует законодательство и не моделирует все права потребителя

## Что отправить на проверку

- Этот репозиторий — исходники и рабочий прототип
- Telegram-бот — удобный способ проверить те же вопросы без локального запуска
- `knowledge_base.json` — база
- `SYSTEM_PROMPT_FILLED.txt` — полный системный промпт
- `CRASH_TEST.md` — фактические результаты трёх вопросов с указанием режима

Режим фактического прогона указан в CRASH_TEST.md. Результаты автотестов с подменённым API не выдаются за реальные ответы модели. Локальный запуск позволяет повторить LLM-прогон без регистрации и API-ключей.
