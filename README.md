# Помощник магазина X1

Небольшой прототип для тестового: чат, шесть пунктов регламента, системный промпт и воспроизводимый краш-тест. Python 3.10+, без внешних зависимостей.

## Запустить за минуту

```text
python server.py
```

Открыть http://127.0.0.1:8087. Можно задать свой вопрос или нажать на любой из трёх вопросов задания. База и полный промпт раскрываются под чатом.

```text
python -m unittest discover -s tests -v
python run_crash_test.py
```

Второй скрипт сохраняет фактические ответы в `crash_results.json` и `CRASH_TEST.md`, а промпт с подставленным регламентом - в `SYSTEM_PROMPT_FILLED.txt`.

Проверено 19 автотестами: правила возврата, брак, неизвестные данные, попытки подмены правил, ошибочные ответы модели, HTTP API и адаптер LLM. Три обязательных вопроса дополнительно проверены в браузере.

## Как устроено

1. `knowledge_base.json` хранит только шесть правил из задания
2. Вопрос разбирается на темы: товар, доставка, возврат, брак, скидка или неизвестное
3. Код отдельно проверяет индивидуальные заказы, срок возврата, брак и запрет скидок
4. Финальный текст собирается из разрешённых правил. Модель не может передать в ответ произвольную цену, статус или обещание
5. У каждого ответа есть ссылки на использованные пункты базы. Если факта нет, бот сообщает об этом и предлагает уточнить у сотрудника. Реального перевода обращения оператору нет

### Два режима

**Без ключа — автономный FAQ (`rules`).** Разбор формулировок выполняется простыми правилами. Он сразу работает и подходит для проверки задания, но не является LLM и не понимает любые перефразирования. Сложную неизвестную формулировку безопаснее не распознать, чем выдумать ответ.

**С ключом — LLM + проверка регламента (`llm+policy`).** OpenAI Responses API получает системный промпт из файла, регламент и вопрос клиента отдельным сообщением. Structured Outputs ограничивает результат модели списком тем. Python валидирует ответ и формирует текст из базы. Критические случаи имеют независимые проверки в коде. При ошибке или отказе модели включается явно обозначенный `rules-fallback`.

Переменные задаются перед запуском. `.env` автоматически не загружается. Пример для PowerShell:

```powershell
$env:OPENAI_API_KEY = '<ваш API-ключ>'
$env:OPENAI_MODEL = '<доступная вам модель с Responses API и Structured Outputs>'
python server.py
```

Ключ остаётся на сервере, не попадает в браузер и репозиторий. В LLM-режиме вопрос и регламент передаются OpenAI; хранение ответа API отключено параметром `store: false`. Реальные персональные данные для теста не нужны.

## Защита и границы

- По заказу 1842 отсутствует база статусов. Общие условия доставки явно отделяются от статуса конкретного заказа
- Вскрытая упаковка не запрещает возврат до 14 дней; на 16-й день обычный возврат не обещается
- Брак ведёт на экспертизу, без обещания немедленной выплаты и без выдуманного срока экспертизы
- Сообщение клиента не изменяет базу или запрет скидок
- Незнакомые поля и темы из ответа LLM отклоняются; цена, сроки и скидки не генерируются свободным текстом
- Вопросы не сохраняются, браузер вставляет ответы через `textContent`, файлы выдаются по фиксированному списку
- Заявлена проверка конкретных сценариев, а не универсальная защита от любых атак. Модель всё ещё может неверно распознать тему; поэтому важны дополнительные evals на реальных формулировках
- Регламент взят из тестового. Проект не трактует законодательство и не моделирует все права потребителя

## Что отправить на проверку

- Этот репозиторий — исходники и рабочий прототип
- `knowledge_base.json` — база
- `SYSTEM_PROMPT_FILLED.txt` — полный системный промпт
- `CRASH_TEST.md` — фактические результаты трёх вопросов с указанием режима

Включённый в репозиторий прогон выполнен без API-ключа в режиме `rules`. Адаптер API проверяется тестами с подменённым HTTP-ответом; реальный LLM-вызов этим не подтверждается. Для отдельного LLM-прогона надо задать обе переменные и снова запустить `run_crash_test.py`.

Официальная документация использованного API: https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses
